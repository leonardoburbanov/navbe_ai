# Install & distribution

How developers get Navbe on their machine without (or with) a git checkout.
Agent wiring after install is in [connect_agents.md](connect_agents.md).

## End-user install (recommended)

One-liner installers ensure [uv](https://docs.astral.sh/uv/) is present, then
run `uv tool install` so `navbe` and `navbe-mcp` land on `PATH`.

### macOS / Linux / WSL

```bash
curl -fsSL https://raw.githubusercontent.com/leonardoburbanov/navbe_ai_v0.1/main/scripts/install.sh | bash
```

### Windows (PowerShell)

```powershell
irm https://raw.githubusercontent.com/leonardoburbanov/navbe_ai_v0.1/main/scripts/install.ps1 | iex
```

### Direct uv (no script)

```bash
uv tool install git+https://github.com/leonardoburbanov/navbe_ai_v0.1.git
```

### Pin a version

```bash
# bash / WSL
NAVBE_REF=v0.1.0 curl -fsSL …/scripts/install.sh | bash

# PowerShell
$env:NAVBE_REF = "v0.1.0"
irm …/scripts/install.ps1 | iex

# or
uv tool install git+https://github.com/leonardoburbanov/navbe_ai_v0.1.git@v0.1.0
```

Optional overrides for the scripts:

| Env var | Default | Purpose |
| --- | --- | --- |
| `NAVBE_REPO` | `https://github.com/leonardoburbanov/navbe_ai_v0.1.git` | Git remote |
| `NAVBE_REF` | (unset = default branch) | Tag or branch |

### Verify

```bash
navbe --version
navbe-mcp --help    # must exit 0 (does not hang on stdio)
navbe setup
navbe mcp configure
```

## Contributor install (checkout)

```bash
git clone https://github.com/leonardoburbanov/navbe_ai_v0.1.git
cd navbe_ai_v0.1
uv sync
uv run navbe setup
uv run navbe mcp configure   # or use committed .cursor/mcp.json in this repo
```

Inside a checkout, prefer `uv run navbe …` / `uv run navbe-mcp` so you use the
working tree. MCP config generated by `navbe mcp configure` uses
`uv run --directory <repo> navbe-mcp`.

## Data home

| Mode | Default data root |
| --- | --- |
| Tool install (`uv tool install` / install scripts) | `~/.navbe/` |
| Git checkout | repo root |

Files under that root (unless overridden by `NAVBE_*`):

| Path | Role |
| --- | --- |
| `navbe.db` | SQLite control plane |
| `navbe_flows/` | Flow definitions + run artifacts |
| `navbe_credentials.json` | Local secrets (never commit) |
| `navbe_sync.json` | GitHub sync config |

See [agents/operations.md](agents/operations.md) for the full env table.

## Human CLI surface

Agents use **`navbe-mcp`**. Humans use **`navbe`**.

| Command | Role |
| --- | --- |
| `navbe` / `navbe --help` | Interactive slash menu on a TTY; otherwise quick start |
| `navbe setup` | First-run: data dirs, secrets, sync, optional MCP write |
| `navbe info [--json]` | Paths, credential/sync readiness, version |
| `navbe login [--status]` | Recommended key presence (never values) |
| `navbe mcp show` | Print pasteable `mcpServers` JSON |
| `navbe mcp configure` | Merge Navbe into Cursor / Claude Desktop configs |
| `navbe secret …` | Local credentials store |
| `navbe sync …` | GitHub `flows/<id>/flow.json` mirror |
| `navbe flows` / `navbe runs` / `navbe steps` | Browse flows, runs, step catalog |
| `navbe serve` | FastAPI + mounted MCP over HTTP |

`navbe mcp configure` writes:

| Client | Path |
| --- | --- |
| Cursor (global) | `~/.cursor/mcp.json` |
| Claude Desktop (Windows) | `%APPDATA%\Claude\claude_desktop_config.json` |
| Claude Desktop (macOS) | `~/Library/Application Support/Claude/claude_desktop_config.json` |

Flags: `--client cursor|claude|all`, `--dry-run`.

## Distribution artifacts

| Artifact | Location | Notes |
| --- | --- | --- |
| `scripts/install.sh` | repo + GitHub Release | bash installer |
| `scripts/install.ps1` | repo + GitHub Release | PowerShell installer |
| Wheel / sdist | GitHub Release on `v*` tags | from `uv build` |
| Website install page | (your site) | Mirror the one-liners; optional CDN of the scripts |

Release pipeline: [`.github/workflows/release.yml`](../.github/workflows/release.yml)
runs on tag `v*` and uploads wheel, sdist, and both install scripts.

Until the first tag exists, prefer the **raw.githubusercontent.com** script URLs
above. After a release, website hosts can also use:

```text
https://github.com/leonardoburbanov/navbe_ai_v0.1/releases/latest/download/install.sh
https://github.com/leonardoburbanov/navbe_ai_v0.1/releases/latest/download/install.ps1
```

### Cut a release

```bash
# bump version in pyproject.toml / src/navbe/__init__.py as needed
git tag v0.1.0
git push origin v0.1.0
```

GitHub Actions builds and attaches assets to the release.

### Out of scope (today)

- Windows desktop / tray app
- Standalone PyInstaller branded `.exe`
- PyPI publish (optional next step; install uses git / release wheels)
